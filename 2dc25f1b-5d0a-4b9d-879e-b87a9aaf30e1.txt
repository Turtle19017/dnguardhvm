# 0. Mục đích & TL;DR
==========================================================================================
Nối tiếp report gốc (DNGuard_HVM_4.9.6_Runtime_Report). Ghi lại toàn bộ tiến triển kể từ khi chốt
"dừng probe CDB, chuyển sang native in-process JIT shim". Dùng để mở conversation mới khi hết context.

ĐÃ ĐẠT:
1) Native JIT shim hook ranh giới HVM->CoreCLR JIT, thu MỌI method trong 1 lần chạy:
   generated IL + identity(MethodDef) + maxStack + EHcount + locals + resolveToken/getCallInfo/getFieldInfo.
   Không còn probe từng MethodDef.
2) Indexer (gộp corpus -> per-method: IL, meta, tokenmap ảo->thật) + offline rebuilder (C#/dnlib) vá IL vào module dump.
3) GỠ ĐƯỢC nút token ảo (bài toán khó nhất, report §11): ghép callback theo handle -> map virtual->real per-method.
   Xác minh đúng ngữ nghĩa (MemCipher.Encrypt, Program.Main).
4) Module LordsMobileBot: 922 method thu được (IL nhất quán 100%); rebuild 838 method, 730 dịch token trọn vẹn;
   logic thật đã hiện trong dnSpy.

CÒN LẠI: gỡ prologue anti-tamper (v0.6); phục hồi locals kiểu methodSignature (mở khóa Program.Main);
sửa bắt EH; gỡ bootstrap DNGuard để chạy regression 990.

# 1. Kiến trúc 3 công cụ
==========================================================================================
A. DNGuardJitShim (native C++/MinHook) + Launcher (v0.3g):
   Launcher: CreateProcessW(host, SUSPENDED) -> inject shim -> chờ SHIM_READY -> ResumeThread.
   Shim: DllMain tối thiểu -> init thread (ngoài loader lock) -> LdrRegisterDllNotification
         -> clrjit.dll load: MinHook detour getJit. Chạy --mode clrjit-direct (BRANCH B).
   Branch B: hook clrjit!compileMethod THẬT (lưu con trỏ pristine trong getJit detour, trước khi HVM patch),
             gate caller ∈ [HVMRun64.base,.end) (HVM gọi clrjit sau khi dịch).
   Capture: compile_id atomic + TLS compile/callback stack; copy IL ngay; SHA-256;
            đọc CORINFO_METHOD_INFO; hook thụ động resolveToken(28)+getEHinfo(11)+getCallInfo(138)+getFieldInfo(92);
            resolver identity (guarded); writer thread ghi corpus bất đồng bộ.
   Corpus: methods/<compileId>/{method-info.json, generated-il.bin, identity.json, locals.json/.bin, eh.jsonl, callbacks.jsonl}

B. index_corpus.py (v6): key theo (scope, MethodDef token); tự phát hiện module target (--target-ns LordsMobileBot).
   Xuất by-token/<hex>/{il.bin, locals.bin, meta.json, tokenmap.json} + index/stats/scopes/inconsistent.json.
   tokenmap = ghép ảo->thật theo handle, GỘP callbacks qua MỌI compile của method.

C. DNGuardRebuilder (C#/.NET8/dnlib 4.4.0, v0.5b): nạp module dump; mỗi MethodDef: đọc il.bin ->
   PatchTokens(ảo->thật theo tokenmap) -> CreateCilBody(codeSize=il.Length) -> set locals+EH+maxStack ->
   module.Write(PreserveAll). Xuất rebuilt.txt + self-verify.

# 3. Cơ chế HVM
==========================================================================================
1) HVM hook JIT toàn cục -> bắt method của MỌI module (rc-v11: 338 module). PHẢI key (scope,token);
   token đơn va chạm cross-module (0x06000001 = DevExpress ..ctor lẫn LordsMobileBot <Module>.m8DEC...).
2) Generated IL chứa TOKEN ẢO high-RID (0x04800001 Field, 0x01800002 Class, 0x0A800003/0x06800005 Method; RID có bit 0x800000).
   info->ILCode KHÔNG bị patch in-place (before==after, kiểm 5478 method). HVM dịch ảo->thật qua bảng nội bộ + ICorJitInfo wrapper.
3) Hai tầng resolveToken: ta hook tầng CEEInfo (sau dịch) -> thấy token THẬT. getCallInfo/getFieldInfo nhận token ẢO -> resolve handle thật.
   Mỗi member gọi 2 lần cùng handle: 1 real(resolveToken), 1 virtual(getCallInfo/getFieldInfo).
4) Prologue anti-tamper HẰNG SỐ đầu mọi method:
   ldsflda ZYXDNGuarder::a (ảo 0x04800001); constrained. IntPtr (ảo 0x01800002); callvirt Object::GetHashCode (ảo 0x0A800003); call <junk table bậy> (dead); ... body thật.
   Class token của constrained. là operand ảo DUY NHẤT không bắt qua callback -> nguồn chính của 'unmapped'.

# 4. Đột phá dịch token
==========================================================================================
Map: mỗi member gọi cả token thật (resolveToken) lẫn token ảo (getCallInfo/getFieldInfo) CÙNG handle ->
ghép theo handle -> ảo->thật. Token thật là token hợp lệ trong module (MethodDef 0x06/MemberRef 0x0A/Field 0x04/TypeRef 0x01).
Token ảo per-compile, nhưng IL nhất quán (SHA trùng) -> gộp callbacks mọi compile an toàn.
Rebuild = vá bytes IL (thay operand ảo bằng token thật) rồi dnlib parse -> resolve hết. Không import cross-module.
Xác minh: MemCipher.Encrypt -> key/salt/SignatureKey/Encrypt/RandomNumberGenerator.Fill/BitConverter.ToUInt64;
Program.Main -> Application.add_ThreadException / new ThreadExceptionEventHandler(Application_ThreadException).

# 5. Lỗi & khắc phục
==========================================================================================
- Branch A (getJit proxy) nằm TRÊN HVM -> chỉ thấy stub 0xB. Dùng Branch B (hook clrjit!compileMethod, gate caller∈HVMRun64).
- Crash 0xE0434352 khi tự gọi getEHinfo / deref locals.pSig của method không local. Sửa: HOOK THỤ ĐỘNG; đọc locals chỉ khi numArgs>0 + SEH.
- dnlib CreateCilBody(code,...) tự parse HEADER; il.bin là IL thuần -> phải dùng overload có codeSize=il.Length, exceptions=null, localVarSigTok=0.
- Bỏ KeepOldMaxStack (maxStack sai -> body invalid); để dnlib tự tính.
- Ghi module: MetadataFlags.PreserveAll (giữ token/heap).
- LUÔN lọc (scope,token); scope handle đổi mỗi run.
- 'có tokenmap' != 'đã rebuild'; unmapped=0 mới là dịch trọn.
- dnSpy: mở đúng .rebuilt.dll (không phải dump), tránh cache; method CF-flattened (br.s) lỗi decompiler C# nhưng IL hợp lệ -> xem IL (phím L).
